# Card Lounge — 5ゲームの決定的ルール・CPU・状態遷移

本書は `CARD_LOUNGE_MASTER_SPEC.md` §4.3 の操作判定を実装するための詳細。ゲーム固有のルールは**ここに明記したローカルルールで固定**し、一般に知られる別ルール（七並べの失格制、SpeedのA–K非循環など）と混同しない。

## 0. 共通カード生成と乱数

- スート順：`S`(♠)、`H`(♥)、`D`(♦)、`C`(♣)。ランク順：`1=A,2..10,11=J,12=Q,13=K`。IDは `S-1` 等。
- 52枚作成順：`S-1..13,H-1..13,D-1..13,C-1..13`。ババ抜きは最後に `JOKER` を追加し、**53枚**。
- `nextRng` はxorshift32: `x ^= x<<13; x ^= x>>>17; x ^= x<<5; x >>>= 0`; `0`なら初期化時に`0x6d2b79f5`へ正規化。数値は `(x>>>0)/2**32`。
- `shuffle` は配列の末尾から `j=floor(rnd()*(i+1))` としてswapするFisher–Yates。山札のトップは配列末尾、配るとき`pop()`。初期seedは `crypto.getRandomValues` で得た32bit値。
- CPU選択で乱数を用いたら必ずその消費後の `rng.state` を保存。純粋関数の2回呼び出しで2回抽選しない。実装時には選択操作と乱数更新を一つのイベント／reducerのトランザクションとして扱う。
- `GameEvent` は描画・SEの通知用。ゲーム進行の真実は保存可能なstateのみ。

## 1. クロンダイク・ソリティア

### 1.1 初期配置

1. 52枚をシャッフル。tableauの列0〜6へ左から順に1,2,3,4,5,6,7枚を配り、各列の最後の1枚だけ表向き。`down.length=colIndex`, `up.length=1`。
2. 残り24枚を `stock`（全部裏向き）へ置く。`waste=[]`、4つの `foundations=[]`、`redealCount=0`、`undoStack=[]`。
3. 画面は中央に7列、上部にstock・waste・4組札。全操作可能要素はボタン型でキーボード選択可能。

### 1.2 合法手

- `KL_DRAW`: `stock.length>0` のとき末尾の1枚を`waste`末尾へ表向きで移動。Undo履歴に保存。
- `KL_REDEAL`: `stock.length===0 && waste.length>0` のとき **`stock = [...waste].reverse()`**, `waste=[]`。その後popで元の巡回順に再登場する。無制限に循環できる。Undo履歴に保存。
- `KL_MOVE` 機械判定:
  - source= `waste`: **末尾1枚だけ**。
  - source= `tableau`: `up`の任意の位置から末尾までの連続する表向きの塊。count>=1、連続して**上のカードが下のカードよりランク1小さい、色が交互**。伏せ札を含めない。
  - source= `foundation`: そのスートの末尾1枚だけ（組札から列への戻しを許可）、count=1。
  - target= `tableau`: 空列には**キングの束だけ**。非空列には一番上のカードよりランク1小さく、色違いの先頭カードのみ。
  - target= `foundation`: count=1、スート一致、空ならA、非空なら前回の末尾より1大きい。
  - source と target が同じ位置、`stock`から直接移動、組札間の移動、waste以外から`waste`への移動は不可。
  - tableauのupが空になりdownが残った場合、down末尾をupへ移して自動的にめくる（同一操作）。
- `KL_UNDO`: 最後に成功したカード移動／DRAW／REDEALの前のframeに戻す。履歴最大10フレーム。Undo時も経過時間・ヒント回数は戻さず`assistUsed=true`。直前のUndo操作をUndoとして履歴に積まない。
- `getHint`: 現在見えている合法手のみ。優先順：組札へA・連番→伏せ札をめくれる移動→空列へのキング→waste移動→山札をめくる→再循環。未知stockを調べず、未知札による必勝手を表示しない。合法手がない（循環しているだけ）場合は「山札をめくってください」。

### 1.3 勝敗と終了

すべての`foundations`が各13枚になり52枚が移動すれば `phase=finished`, `outcome=completed`、`score=52`。通常プレイ中の「投了」は保存せず終了扱いで戦績にカウントしない。時間は正味プレイ時間のみ。

### 1.4 状態遷移

`playing`→`KL_DRAW/KL_REDEAL/KL_MOVE`→`playing`（不変条件検証）→`foundations 52`なら`finished`。`KL_UNDO`は`playing`のみ。カードを移動した瞬間に勝利判定、SEやアニメの終了待ちで遅らせない。

## 2. 神経衰弱

### 2.1 モード・作成

- モード `solo` と `vsCpu`。soloではCPUターンを発生させない。
- 難易度はペア数 **8、12、26**。カードペアは同ランクかつ同じ色（例`H-5`と`D-5`、`S-5`と`C-5`）。52枚は26種類のpairKeyを構成する。選んだペア数だけ抽出し、全タイルをシャッフル。16/24/52枚のグリッド（4列×4行、6列×4行、13列×4行の固定表示はしない。幅で列数を自動調整）。
- タイルは `faceUp=false`, `matched=false`、`turn=human`、`pickedTileIds=[]`, `resolution=idle`、`attempts={human:0,cpu1:0}`。

### 2.2 ターン

1. `MEM_FLIP`を合法とする条件: `phase=playing`、actor===turn、resolution===idle、tileが未一致・裏向き・選択0～1枚、同じtileを重複選択しない。
2. 1枚目を表、同じプレイヤーが2枚目を表。**attempts[actor]++ は2枚揃った時だけ**。
3. pairKeyが一致したら即 `matched=true`, `faceUp=true`、`pairsWon[actor]++`、`pickedTileIds=[]`。同じ人が次手番（`vsCpu`のCPUも同様）。
4. 不一致なら `resolution='mismatch'`。両方が**800ms**表のまま表示、他入力不可。コントローラーが`MEM_RESOLVE_MISMATCH`を1回発行し2枚を裏返す。`pickedTileIds=[]`, `resolution='idle'`、`vsCpu`は次の人へ、soloはhuman継続。
5. すべてのペアが一致で `finished`。solo=`completed`; vsCPUでhuman>cpuはwin、human<cpuはloss、同数draw。

**中断時の不一致:** `pickedTileIds` と`resolution`を保存し、再開時に新たな800ms待機後に解決。取りこぼしたタイムアウトによりカードが表面で固定されないようにする。画面非表示の間に進ませない。

### 2.3 CPUの記憶と能力

- CPUには自身／人間が実際に公開したタイルIDとpairKeyだけを観測させる。裏面の「真のpairKey」配列を読むことは禁止。実装では `observed: Record<string, string>` 形式の公開情報メモを維持し、**CPUがまだめくっていないtileは`observed`に書かない**。§3の`cpuMemory:string[]`は「観測済タイルIDの順序」とし、追加の`cpuObserved:Record<string,string>`をMemorySessionの必須フィールドとして定義する。
- easyは直近2枚、normalは直近6枚、hardは観測した全ての位置・pairKeyを記憶。上限を超えたら最も古いものを忘れる。matched位置は記憶から除去。
- 2枚既知の一致ペアがあればその2枚を選択。1枚目の公開後に同じpairKeyの既知カードがあればそれを選ぶ。ない場合は**未観測・未一致・未公開タイルから一様ランダム**。未観測がなければ合法な未一致カードからランダム。1枚目と同じタイルは選ばない。
- 乱数による選択も公開状態の選択結果だけを返し、UI上で伏せ札の中身を予告しない。CPU1手目600ms、2手目600msを基準にし、難易度では記憶能力を変更（反応時間差による有利不利を主にしない）。

### 2.4 ヒント

合法な未一致タイルを1枚目として選択可能な位置を示すのみ。相手の隠れカードを見せない。soloでも「次の答え」を漏らさない。soloの `memory-perfect` 実績は`attempts.human === pairsWon.human`のときに成立。

## 3. ババ抜き

### 3.1 参加者・カード

- 常に4人: `human,cpu1,cpu2,cpu3`、席は時計回りにこの順。カード52枚＋ジョーカー1枚=53枚。
- シャッフルした53枚を順番に配る（1人14枚、残り3人13枚）。配った直後、手札から同ランク2枚ずつ（スート無関係）を除外。4枚同ランクなら2組を除去。ジョーカーにペアなし。
- 除去したカードは `discarded:CardId[]` に蓄積し、`hands + discarded`が常に53IDとなる。`discarded`には同ランクの2枚単位で追加する。
- 初期手札は表示上ランク順（人間のみ表を見られる）。CPUは各プレイヤーから見える裏面をシャッフルし、ランクの偏りを表示で推測させない。
- 初期手札が0枚になった参加者は `finishedOrder` に記録し、手番をスキップ。最初の手番は`human`から始め、空手札なら次の参加者。

### 3.2 カード引き・自動ペア廃棄

- `turn`の人が、時計回りで次に手札が1枚以上あるプレイヤーから1枚引く。自分以外の有効な対象がいなければ終了判定。
- 人間ターンは対象CPUの裏向きカードから位置を選択し`OM_DRAW{actor:'human',targetIndex}`。CPUターンは対象者の手札位置を一様抽選。
- 引いたカードは手番プレイヤーに移し、その場で同ランクのペアができればその2枚を捨てる。引き元の人が手札0になった場合も終了順に追加。
- 手番プレイヤーのカード順を再シャッフルしてから次へ（`rng`更新）。CPU相手のカード表面を見せない。人間が引いた結果は人間の手札から確認可能。
- 手番プレイヤーが手札0になったら`finishedOrder`へ追加。次は次の非空手札者。1人だけがカードを持っていたらその人に残る1枚はJOKERであることを検証し `finished`。敗者=その人。人間以外にJOKERが残った場合、人間は`win`。

### 3.3 CPU・ヒント

CPUは相手の**カード裏面の位置**のみをランダム選択する。`targetIndex`を決める際にカードIDやJOKER位置を見ない。戦略・難易度設定は不要で常に公平乱択。CPU操作間隔700ms。ヒントは「隣のプレイヤーからカードを1枚選んでください」と説明するだけで、ジョーカー位置を指示しない。

### 3.4 進行不能・勝敗

- ペア消去直後にカード枚数は2枚単位で減る。最後の1枚はジョーカー。
- すべてのカードが `discarded` になったら不正（1枚のJOKERは必ず残る）としてデータ検証失敗。
- UI上の演出は「カードを引く→ペアが捨てられる→手番が進む」順。カード表裏情報は結果ダイアログ以外で漏らさない。

## 4. 七並べ

### 4.1 初期化と公開盤面

- 52枚を4人へ13枚ずつ配る。
- 4種類の「7」を配札者の手札から取り除き、中央の4レーンの7として配置。各lane `{low:7,high:7}`。残りの手札合計48枚。
- 開始手番: ♦7の元の所持者の**次**の席（`human→cpu1→cpu2→cpu3→human`）、その人が手札0なら飛ばす。
- 盤面はスートごとにA〜Kの横一列表示。7の位置を固定し、未配置スロットを薄く表示。

### 4.2 合法手とパス

- `SV_PLACE{actor,cardId}`は、自分の手番かつ手札にある札で、同スートの`low−1`または`high+1`のランクなら合法。例えば♥7の周囲は♥6または♥8、♥6後に♥5が可能。
- 設置で `lane.low/high`更新、手札から除去、残り手札0なら `finishOrder` に記録。次の未終了者へ移る。
- `SV_PASS`: **合法手が1枚以上ある時**は自発的パス。残り自発パス回数が1以上のときだけ可能。3回使用後は合法カードを出さなければならない。
- **合法手が0枚の時**は強制パス。`forcedPasses[actor]++`、自発的パス回数には加算しない。何回でも可能。ただし最終的に全カードが配置できる構造なので理論上の永続停滞は生じない。実装は「1周で誰も置けない」時に整合性エラーを出し暴走を止める。
- `finishedOrder` は手札が空になった順。最後のプレイヤーも最後の札を出したら終了。全52枚が盤面に乗れば `finished`。人間順位1なら`win`、その他`loss`。
- 自発パスはCPUは使わず、合法手がなければ強制パス。人間の手動パス時は確認ダイアログは不要だが残回数を表示。

### 4.3 CPUロジック（見えない相手の札を参照禁止）

- easy: 合法な手札から一様ランダム。
- normal: 候補を置いた後、自分の手札で直ちに続けて出せる隣接札が何枚あるかを測り、最多を選ぶ（同点はスートとランク順）。
- hard: normalに加えて同スートの手札の連続ランク鎖の長さ（次の2〜4枚を仮置き可能な数）を評価し最長を選ぶ。同点なら今の自分の残りカードが多いスート優先、なお同点ならスート順・ランク昇順。
- 誰の手札を推測したかのような「相手が持つ数字」の情報は使わない。実際に盤面で見える値だけを参照。
- CPU行動間隔easy 1100ms、normal 750ms、hard 500ms。CPU合法手0なら`SV_PASS`を発行。

## 5. スピード

### 5.1 採用するローカルルールの定義

**CPUと同時進行の簡易スピード（1対1）**。地域・アプリによる変種があるため、ここに定めるルールをローディング／ルール画面に表示する。

1. 52枚をhumanとcpu1へ各26枚ずつ。各人は自分のカードを4枚表向きの場（visible slots）に置き、1枚を中央へ表向きに置く。残り21枚は自分の裏向き補充山（reserve）。中央の2枚は最初から両者が使用できる。
2. 自分の4枚の表向きカードのうち、中央いずれかの一番上の数字と±1のカードを**いつでも**中央へ出せる。スートは関係なし。A(1)とK(13)も隣接とする。
3. 出したvisibleの枠が空いたら自分のreserveのトップから即1枚表向きに補充。reserveが空なら枠はnullのまま。
4. `SP_PLACE{actor,visibleIndex,center}` は現在のstateで原子的に検証。human/cpuが同じ中央へ置こうとしたら**先に処理された方のみ確定**し、後の操作は新しい中央札で再検証。合法でなければ状態を変えない。
5. 双方のvisibleから2つの中央へ合法手が**1つもない**とき、 `SP_RESET_CENTERS` で、reserveのある人は自分のreserveのトップを対応する中央へ1枚置き直す（**旧中央札は同じ山に残る**）。片方だけreserveがあれば1枚だけ置く。2人ともreserve0なら補充不可。補充が終わっても手がない場合は同じ処理を繰り返せるが、CPUループは毎回150ms以上間隔を空ける。
6. 自分のreserve=0かつvisible4枠が全てnullになった瞬間、その人が`win`。CPUが先なら人間は`loss`。両者が同一の原子的更新で同時に0になることは通常ありえない（1アクション1人）。
7. **手詰まり**: 両者から合法手0かつ両者reserve0の場合、残るvisibleの枚数が少ない方を勝者、同数ならdraw。手詰まりによる勝敗は結果に「手詰まり判定」と明記する。

### 5.2 CPU動作

- `chooseSpeedCpuAction`は自分の4枠と**その時点の**中央トップだけを見る。すべての合法組（slot, center）を列挙し、選択する。easyは合法候補からランダム。normal/hardは **出せる合法候補を優先しつつ、山札の未来や人間の非公開札を参照しない**。normal/hardの同点選択規則は `visibleIndex` 昇順、`center` はhuman→cpu1。
- 反応目安easy:1100ms、normal:700ms、hard:400ms。リアルタイムであるため各反応は厳密保証しないが、重複タイマーを発生させない。
- 自動中央更新が必要な時はCPUの連打やhuman操作より優先して、処理を1回だけ発行。更新直後に双方の合法手を再評価。
- CPUが画面操作の`pointerup`前に中央札を書き換えた場合、human操作も現時点の盤面で再検証し、不合法なら「場札が変わりました」と表示しカードを元の位置に描画する。

### 5.3 一時停止・タイマー

- スピードはプレイヤーのゲーム内タイマーとCPU思考タイマーの双方を停止する。タブ非表示は即paused。再開ボタン押下後、**3→2→1** のカウントダウンを表示してから同時進行（カウントダウン中は`paused`を維持し、終了時に`RESUME`）。
- 不正な高速入力を許容しない。pointerイベントでは操作ごとに1回しかreducerへ送らない。

## 6. すべてのゲームで共通の成立条件

1. **勝敗確定は各sessionIdで1回**。最後のカード操作で `phase=finished` にし、`gameFinished`を発行。ゲーム履歴・実績書込は冪等。
2. **CPU以外の操作の優先度:** 同一時点にhumanとCPUが操作した場合、reducerへ先に届いた操作が先に判定される。スピード以外はターン所有者以外の操作がエラー。
3. **不変条件:** カード重複なし、枚数整合、無効なrank/suitなし、ターンは有効な参加者、`finishOrder`は重複なし、phaseとresultの整合。
4. **データ移行:** v1で開始。未知のスキーマを勝手に初期化せず、ユーザーの確認を受ける。
5. **可視情報の境界:** 表向きカード／盤面と、CPU自身の手札だけがCPU判断材料。保存データに裏札が含まれても、CPUに渡す観測Viewへ変換してから計算。
6. **アクセシビリティ:** 神経衰弱の裏札のaria-labelは「裏向きカード 7番」、ババ抜きCPUの札は「CPU2の裏向きカード 3番」。裏側の実カードIDは読み上げない。
7. **端末内ランキングのみ**。複数端末を合わせたランキングはしない。
